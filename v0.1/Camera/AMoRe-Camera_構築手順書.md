# ■ [AMoRe v0.1 カメラPC セットアップ]
([2026/10/10])

# 概要
- **目的**: [カメラPCのブラウザから、USBカメラの映像とマイク音声をAMoRe ServerへWebRTCで送信できるようにする]
- **理由・背景**: [AMoRe要件定義書 v2 の開発段階1。映像送信用の専用アプリは不要とし、HTTPSで公開した送信画面を使う]
- **前提条件**:
  - 構築済み機器
    - AMoRe Server `10.40.0.20`（[AMoRe v0.1 Server 構築] 完了済み）
  - カメラPC
    - Windows 11（他OSは未検証）
    - Chromium系ブラウザ：Google Chrome または Microsoft Edge の最新安定版
    - 1080p・30fpsを出力できるUSB Webカメラ、必要に応じてマイク
  - ネットワーク
    - カメラPCから `10.40.0.20` の `443/tcp` と、送信するカメラのWebRTCポート（`8189`～`8192/udp` のうち管理Webに表示された番号。cam1=8189）へ到達できること
  - カメラの登録
    - 送信先のカメラIDを、Serverの管理Web（`https://10.40.0.20/admin/`）で事前に追加しておく。追加するとServer上にそのカメラ専用のコンテナが作成される
    - 例：カメラPCをVLAN30（`10.30.0.0/16`、GW `10.30.0.1`）に接続し、x530L のVLAN間ルーティングでVLAN40のServerへ到達する
  - 送信画面
    - `v0.1/Camera/www/`（AMoRe Server が `https://10.40.0.20/` で配信する。カメラPCへの配置作業は不要）
  - **将来性**
    - 開発段階2：カメラPCの監視・ログ収集エージェント（要選定）
    - 開発段階3：4K（3840×2160）送信

## 送信画面の機能

| 機能 | 内容 |
| --- | --- |
| カメラID | 送信先（管理Webで登録したカメラ。最大4台）。OBSのメディアソースと1対1で対応する |
| カメラ・マイク選択 | 接続中のデバイスから選択。送信中の変更はその場で差し替える |
| 音声の有効・無効 | 無効にすると映像のみ送信。マイクを取得できない場合は理由を表示し「映像のみで送信する」を選べる |
| 映像品質 | 自動（推定帯域で1080p⇔720p）／1080p固定／720p固定 |
| 送信状態 | 接続状態、コーデック、実際の解像度・FPS・ビットレート、推定帯域、RTT、経路（直接／TURN） |
| 自動再接続 | 切断時に 1秒→2秒→4秒→以降4秒 で再試行。停止ボタンで終了 |

- 映像はH.264を優先する。ブラウザがH.264を使えない場合はVP8で送信し、ServerでH.264へ変換する（Serverの負荷が増える）。
- 品質調整の閾値（暫定）：推定帯域4.5Mbps未満が5秒継続→720p、8Mbps以上が15秒継続→1080p、復帰後15秒以内の再低下→30秒復帰保留。値はServerの `AMoRe.yaml` で変更する。
- WebRTCには目標ビットレートの指定がないため、送信の上限を目標値（1080p：6Mbps、720p：3Mbps）に設定する。「1080p固定（上限ビットレート）」を選ぶと上限値（8Mbps）で送信する。

# 構築手順

### [ネットワーク到達確認]
  PowerShellで実行する。
  ```powershell
  ipconfig
  Test-NetConnection 10.40.0.20 -Port 443
  ```
  - `TcpTestSucceeded : True` であること
  - `SourceAddress`・`InterfaceAlias` が想定した有線NICであること（Wi-Fi・VPN経由の成功と取り違えない）

### [Server証明書の取得]
  AMoRe Server が作成した自己署名証明書 `server.crt` をカメラPCへコピーする。秘密鍵 `server.key` はコピーしない。
  ```powershell
  scp amore@10.40.0.20:/opt/AMoRe/v0.1/Server/certs/server.crt "$env:USERPROFILE\Downloads\amore-server.crt"
  certutil -dump "$env:USERPROFILE\Downloads\amore-server.crt" | Select-String "Cert Hash\(sha256\)"
  ```
  - 表示されたSHA256の値が、Server構築時に記録したフィンガープリントと一致することを確認する（区切り文字の有無は無視して比較する）
  - `scp` が使えない場合は、USBメモリ等で `server.crt` だけを受け渡す

### [証明書の信頼登録]
  ログオン中のユーザーの「信頼されたルート証明機関」に登録する（管理者権限は不要）。
  ```powershell
  certutil -user -addstore Root "$env:USERPROFILE\Downloads\amore-server.crt"
  ```
  - 確認ダイアログで発行先が `AMoRe 10.40.0.20` であることを確認して「はい」
  - ブラウザをすべて閉じてから開き直す
  - 自己署名証明書を信頼させる暫定運用。正式な証明書管理は要確定事項（HTTPS・ネットワーク）で決める

### [OSのカメラ・マイク利用許可]
  - Windowsの `設定` → `プライバシーとセキュリティ` → `カメラ` / `マイク`
    - 「カメラへのアクセス」「マイクへのアクセス」がオン
    - 「デスクトップアプリがカメラにアクセスできるようにする」がオン（Chrome・Edgeはデスクトップアプリとして扱われる）
  - 会議アプリなど、カメラを使用する他のアプリを終了する

### [電源設定]
  - 送信中にスリープ・画面ロックしないよう、`設定` → `システム` → `電源` で「画面の電源を切る」「スリープ」を「なし」にする
  - バックグラウンド化・画面ロック・スリープ時の送信継続は未検証のため、送信中はブラウザのタブを前面に表示したままにする

### [送信画面を開く]
  ブラウザで次を開く。
  ```text
  https://10.40.0.20/
  ```
  - 証明書の警告が出ないこと（出る場合は「証明書の信頼登録」を確認する）
  - 右上の状態が「待機中」、カメラIDに管理Webで登録したカメラ（例：`ステージ正面（cam1）`）が表示されること
  - 「カメラが登録されていません」と表示された場合は、管理Webでカメラを追加してから再読み込みする
  - 管理Webのカードにある `送信画面` リンク（`https://10.40.0.20/?camera=cam1`）から開くと、そのカメラIDが選択された状態になる

### [デバイスの許可とプレビュー]
  1. `カメラID` で送信先を選ぶ（他のカメラPCと重複させない）
  1. `プレビュー` を押し、ブラウザの「カメラとマイクの使用」を `許可`
  1. `カメラ`・`マイク` で使用するデバイスを選ぶ
  1. 送信状態の `解像度` が `1920×1080（カメラ出力）` であること
      - 1080p未満の場合は注意が表示される。カメラの対応解像度・USB接続（USB3.0ポート推奨）を確認する
  1. 音声を使わない場合は `音声を送信する` を外す
  1. `エコーキャンセル・ノイズ抑制・自動音量調整` はブラウザの音声処理。既定はオン。有効・無効の運用は要確定事項のため、試験時は設定値を記録する

### [送信開始]
  1. `送信開始`
  1. 右上の状態が `接続中` → `送信中`（緑）になること
  1. 送信状態を確認する

      | 項目 | 期待値（LAN・十分な帯域） |
      | --- | --- |
      | コーデック | `H264`（`VP8` の場合はServerで変換される） |
      | 解像度 | `1920×1080` |
      | FPS | `30 fps` 前後 |
      | 映像ビットレート | 6Mbps 前後まで上昇 |
      | 経路 | `直接接続` |
      | 品質 | `1080p30` |

  1. OBS手順書のドック、または Server の `https://10.40.0.20/api/v1/status` で該当カメラが `受信中` になったことを確認する

### [詳細確認（必要時）]
  - Chromeで `chrome://webrtc-internals`（Edgeは `edge://webrtc-internals`）を開くと、コーデック・送信ビットレート・`qualityLimitationReason`（CPU・帯域による制限）を確認できる
  - 試験記録には、カメラPCのCPU・GPU・メモリ、カメラ型番、OS・ブラウザのバージョン、コーデック、実際の解像度・FPS・ビットレート、TURN経由の有無を残す（要件定義書 v2「共通条件」）

### [停止]
  - `停止` を押す。Server側のセッションも終了し、OBSの該当ソースは映像なしになる
  - タブを閉じた場合も終了を通知する（届かない場合はServer側でタイムアウトにより破棄される）

# 確認項目

| 確認 | 期待値 |
| --- | --- |
| 証明書 | `https://10.40.0.20/` で警告なし |
| 送信 | 状態 `送信中`、コーデック `H264`、`1920×1080`・`30 fps` |
| 再接続 | LANケーブルを10秒抜いて戻すと `再接続待ち` → `送信中` に戻る（停止操作なし） |
| 重複接続 | 別のPCで同じカメラIDを選ぶと「別の送信画面から送信中です」と表示され、既存の送信は継続する |
| 映像のみ | `音声を送信する` を外すと `音声：送信しない` で送信でき、OBSで映像が表示される |

# 切り戻し手順

1. 送信画面で `停止` を押し、タブを閉じる。
1. 登録した証明書を削除する場合
    ```powershell
    certutil -user -viewstore Root
    ```
    で `AMoRe 10.40.0.20` のシリアル番号を確認し、次で削除する。
    ```powershell
    certutil -user -delstore Root <シリアル番号>
    ```
1. 送信画面が保存した選択内容（カメラID・デバイス等）は、ブラウザのサイトデータ削除で消える。
- Windows のプライバシー設定・電源設定を変更した場合は、変更前の値に戻す。

# トラブルシューティング

| 表示・症状 | 確認・対処 |
| --- | --- |
| 「この画面は HTTPS で開いてください」 | `http://` ではなく `https://10.40.0.20/` で開く |
| 証明書の警告（NET::ERR_CERT_AUTHORITY_INVALID） | 「証明書の信頼登録」を実施し、ブラウザを開き直す。Serverの証明書を作り直した場合は再登録する |
| 「設定を取得できません」 | Serverが停止している。Server手順書の「起動する」を確認 |
| 「カメラの利用が許可されていません」 | アドレスバー左のサイト情報 → カメラ・マイクを「許可」。Windowsのプライバシー設定を確認 |
| 「カメラを開けません」 | 他のアプリがカメラを使用中。終了してから `プレビュー` |
| 「マイクの利用が…」＋「映像のみで送信する」 | マイクの許可・接続を確認する。映像だけ送る場合はボタンを押す |
| 「カメラが切断されました」 | USB接続を確認し、`送信開始` からやり直す（自動では再開しない） |
| `接続中` のまま → `再接続待ち` を繰り返す | そのカメラのWebRTCポート（例：`8189/udp`）がServerへ届いていない。管理Webでそのカメラのコンテナが `稼働中` か確認する。カメラPCのVPN・ファイアウォール、Serverの `server.public_host`・firewalld を確認 |
| 「別の送信画面から送信中です」 | 同じカメラIDを他のPC・タブが使用中。別のIDを選ぶ |
| コーデックが `VP8` | ブラウザ・OSでH.264エンコーダーが使えない。Chrome/Edgeの最新版を使う。VP8のままでも送信できるがServerのCPU負荷が高い |
| 品質が `720p30` に下がる・帯域不足の表示 | 回線の帯域不足。有線接続にする、他の通信を止める。手動で `1080p 固定` も選べる |
| `推定帯域を取得できないため自動切替不可` | ブラウザが推定帯域を提供していない。`映像品質` を手動で選ぶ |
| FPSに「30fps 未達: CPU負荷」 | カメラPCのCPU不足。他のアプリを終了する、`720p 固定` にする |
| 経路が `TURN経由` | TURNを経由した結果は直接接続と分けて記録する（要件定義書 v2） |
