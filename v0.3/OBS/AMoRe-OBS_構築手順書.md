# ■ [AMoRe v0.3 OBS（編集PC）セットアップ]
([2026/10/10])

# 概要
- **目的**: [編集PCのOBSで、AMoRe Serverが提供する最大4カメラのSRTストリームを同時に受信し、合成・切り替え・配信できるようにする]
- **理由・背景**: [AMoRe要件定義書 v2 の開発段階1。初期版の映像受信はOBS標準の「メディアソース」を使い、OBSプラグインは実装しない]
- **前提条件**:
  - 構築済み機器
    - AMoRe Server `10.40.0.20`（[AMoRe v0.3 Server 構築] 完了済み）
    - カメラPC（[AMoRe v0.1 カメラPC セットアップ] で送信できる状態）
  - 編集PC
    - メインPC：Windows 11、X520（イーサネット 7）`10.30.0.10/16`、GW `10.30.0.1`、x530L `port1.0.26`（access VLAN30）
    - [OBS Studio](https://obsproject.com/ja) 31 以降（使用したバージョンを記録する）
  - ネットワーク
    - 編集PCから `10.40.0.20` の `443/tcp`・`8890-8893/udp` へ到達できること（VLAN30→VLAN40はx530Lでルーティング）
  - カメラの登録
    - 受信するカメラを、Serverの管理Web（`https://10.40.0.20/admin/`）で追加済みであること。カメラごとに専用コンテナとSRTポートが割り当てられる
  - 使用ファイル
    - `v0.3/OBS/scene-collection/AMoRe_v0.3.json`：シーンコレクション（メディアソース4つ＋シーン5つ）
    - `v0.3/OBS/dock/`：状態表示ドック（AMoRe Server が `https://10.40.0.20/obs/` で配信）
  - **将来性**
    - OBSプラグインによる接続先選択・状態表示（実装時期は要確定）。v0.3 はカスタムブラウザドックで代替する

## 受信の仕組み

| 項目 | 値 |
| --- | --- |
| 伝送方式 | SRT（Server＝Listener、OBS＝Caller） |
| コンテナ / コーデック | MPEG-TS / 映像 H.264・音声 AAC-LC 48kHz |
| カメラの識別 | カメラごとのSRTポート（追加順に cam1=`8890`, cam2=`8891` …）と Stream ID `read:<カメラID>` |
| 接続URL | `srt://10.40.0.20:8890?streamid=read:cam1&latency=120000` |
| SRT遅延 | URLの `latency` はマイクロ秒。`120000` = 120ms（LAN暫定値）、WAN試験は `200000` |

- 接続URLは管理Web・ドックの `コピー` ボタンで取得できる（`AMoRe.yaml` のカメラ設定から生成される）。**ポートはカメラごとに異なる**ため、必ず表示された値を使う。

# 構築手順

### [ネットワーク到達確認]
  PowerShellで実行する。
  ```powershell
  Test-NetConnection 10.40.0.20 -Port 443 -InformationLevel Detailed
  ```
  - `TcpTestSucceeded : True`、`SourceAddress : 10.30.0.10`、`InterfaceAlias : イーサネット 7` であること
  - Wi-Fiにもデフォルトゲートウェイがある場合、`10.40.0.20` 宛てがWi-Fiを経由していないことを確認する（[AT-x530L-28GTX 26ポートルーティング設定]「Windowsログの確認結果」参照）

### [Server証明書の信頼登録]
  ドック（OBS内蔵ブラウザ）がHTTPSで接続するため、カメラPCと同じ手順で証明書を登録する。
  ```powershell
  scp amore@10.40.0.20:/opt/AMoRe/v0.3/Server/certs/server.crt "$env:USERPROFILE\Downloads\amore-server.crt"
  certutil -dump "$env:USERPROFILE\Downloads\amore-server.crt" | Select-String "Cert Hash\(sha256\)"
  certutil -user -addstore Root "$env:USERPROFILE\Downloads\amore-server.crt"
  ```
  - SHA256がServer構築時に記録したフィンガープリントと一致することを確認してから登録する
  - SRTの受信自体は証明書を使わない

### [OBSのインストール]
  - [OBS公式](https://obsproject.com/ja/download) からWindows版をインストールする
  - `ヘルプ` → `OBS Studioについて` でバージョンを確認し、記録する
  - `設定` → `映像`：基本（キャンバス）解像度 `1920x1080`、FPS `30`

### [シーンコレクションの取り込み]
  1. リポジトリの `v0.3/OBS/scene-collection/AMoRe_v0.3.json` を編集PCへ用意する
      - JSONは、管理Webで `cam1`～`cam4` を順に追加した場合のURL（cam1=`8890` … cam4=`8893`）を設定している
      - ServerのIP・カメラID・ポートの割当（削除・再追加で変わる）・`srt.latency_ms` が異なる場合は、取り込み前にJSON内の `srt://...` を書き換えるか、取り込み後に各メディアソースの `入力` を管理Webに表示されたURLへ直す
  1. `シーンコレクション` → `インポート` → `コレクションパス` に上記JSONを指定 → `インポート`
  1. `シーンコレクション` → `AMoRe v0.3` を選択
  1. 次が作成されていること

      | 種類 | 名前 | 内容 |
      | --- | --- | --- |
      | シーン | `AMoRe 4分割` | 4カメラを2×2で表示 |
      | シーン | `AMoRe CAM1`～`AMoRe CAM4` | 各カメラを全画面表示 |
      | メディアソース | `AMoRe cam1`～`AMoRe cam4` | 各カメラのSRT受信（シーン間で共有） |

### [メディアソースを手動で作成する場合]
  シーンコレクションを使わない場合、または追加・修正する場合は、`ソース` → `＋` → `メディアソース` で次のとおり設定する。

  | 項目 | 設定値 |
  | --- | --- |
  | ローカルファイル | オフ |
  | 入力 | 管理Web・ドックに表示されたSRT URL（例：cam1 `srt://10.40.0.20:8890?streamid=read:cam1&latency=120000`、cam2 `srt://10.40.0.20:8891?streamid=read:cam2&latency=120000`） |
  | 入力フォーマット | `mpegts` |
  | 再接続の遅延 | `1` 秒 |
  | ネットワークバッファリング | `1` MB |
  | 可能な場合はハードウェアデコードを使用 | オン |
  | ソースが非アクティブのときにファイルを閉じる | **オフ**（シーン切り替えのたびに再接続して表示が遅れるのを防ぐ） |
  | ソースがアクティブになったときに再生を再開する | オフ |

### [音声ソースの選択]
  - 取り込み直後は `AMoRe cam1` だけミュート解除、`cam2`～`cam4` はミュートになっている
  - 複数マイクの同時使用による重複音声・エコーを避けるため、配信に使う音声ソースだけをミュート解除する（要件定義書 v2「音声仕様」）
  - 音声を確認する場合は `オーディオの詳細プロパティ` で該当ソースの `音声モニタリング` を `モニターのみ` にする（配信には出ない）。確認後は `モニターオフ` に戻す

### [状態表示ドックの追加]
  1. `ドック` → `カスタムブラウザドック`
  1. 次を追加して `適用`
      ```text
      ドック名 : AMoRe
      URL      : https://10.40.0.20/obs/
      ```
  1. ドックにカメラごとの状態（`未送信`／`変換準備中`／`受信中・OBS接続 N`／`不調`）とSRT URLが表示されること
  1. v0.3 で追加した表示（Server 側で有効にしている場合）

      | 表示 | 内容 |
      | --- | --- |
      | `● 録画` | そのカメラを録画中 |
      | `不調`（赤） | カメラのコンテナが不調。理由と自動復旧の状況が表示される。対処は Server の管理Webで行う |
      | `★ AIの推奨: …`（緑枠） | AI が「今使うと良い」と提案したカメラと理由（提案のみ。シーンは自動で切り替わらない） |
      | `⚠ …`（橙） | AI が映像の異常（真っ暗・傾き等）を検知した |

  - 全カメラを1画面で確認したい場合は、Server のモニター画面 `https://10.40.0.20/admin/monitor.html` をブラウザ（または OBS の別のカスタムブラウザドック）で開く
  1. 右上が `Server 接続中` であること

# 受信確認

### [1台ずつ確認]
  1. カメラPCで `cam1` の送信を開始する
  1. ドックの `cam1` が `受信中・OBS接続 1` になること
      - `H264 / Opus → H264 / AAC（映像は再エンコードなし）` と表示される（VP8の場合は `H.264へ変換中`）
  1. `AMoRe CAM1` シーンで映像が表示され、音声メーターが動くこと
  1. `AMoRe cam1` を右クリック → `プロパティ` の表示、または `ツール` → `ログ` → `現在のログを表示` で映像が `1920x1080` であることを確認する

### [4台同時確認]
  1. `cam1`～`cam4` を同時に送信する
  1. `AMoRe 4分割` で4映像が同時に表示されること
  1. ドックの4台すべてが `受信中・OBS接続 1`
  1. 状態表示を記録する：`表示` → `ステータスバー` のCPU・ドロップフレーム、`表示` → `ドック` → `統計`

### [遅延・同期の簡易確認]
  正式な測定方法は要件定義書 v2「性能測定・受け入れ条件」に従う。ここでは導入確認として行う。
  - **映像遅延**：カメラにミリ秒表示のタイマー（別PCの画面等）を映し、そのタイマーとOBSのプレビューを同じカメラ（スマートフォン等）で同時に撮影して差を読む。目標はLANで500ms以下（95パーセンタイル）
  - **音声・映像同期**：手を叩く・カチンコ等、光と音が同時に出る素材を撮影し、OBSの録画を動画編集ソフトでコマ送りして差を読む。目標は80ms以内
  - **SRT遅延の交渉結果**：`ツール` → `ログ` に記録されたSRT接続時の情報を確認し、試験記録に残す（要件定義書 v2：OBS側との実際の交渉結果を記録）

### [切断からの復旧確認]
  1. 4台受信中に、カメラPC1台のLANケーブルを10秒抜いて戻す
  1. カメラPCの送信画面が `再接続待ち` → `送信中`、OBSの該当ソースが10秒以内に再表示されること
  1. Server側の再起動（`docker compose restart`）後も、OBSのメディアソースが自動で再接続すること（`再接続の遅延 1秒` で再試行される）

# 切り戻し手順

1. `シーンコレクション` で元のコレクションへ切り替える。不要なら `シーンコレクション` → `削除` で `AMoRe v0.3` を削除する。
1. `ドック` → `カスタムブラウザドック` で `AMoRe` を削除する。
1. 証明書を削除する場合は Camera 手順書の切り戻し手順と同じく `certutil -user -delstore Root <シリアル番号>` を実行する。
- 編集PCのIP・x530Lの設定は本手順で変更しないため、切り戻し対象外。

# トラブルシューティング

| 症状 | 確認・対処 |
| --- | --- |
| ドックが空白・証明書エラー | 証明書の信頼登録後、OBSを再起動する。URLが `https://10.40.0.20/obs/` か |
| ドックが `Server 接続不可` | 編集PCから `Test-NetConnection 10.40.0.20 -Port 443`。Serverの稼働状態 |
| ドックが `コンテナ管理 停止` | ServerのAMoReがDockerに接続できない。管理Webの表示とServer手順書のトラブルシューティングを確認 |
| ドックが `処理停止` | そのカメラのコンテナが停止・未作成。管理Webで `再起動` し、`ログ` を確認 |
| ドックが `未送信` | カメラPCで該当カメラIDの送信が開始されていない |
| ドックが `変換準備中` のまま | ServerのFFmpegが起動に失敗している。`docker compose logs mediamtx` を確認 |
| ドックは `受信中・OBS接続 0` で黒画面 | OBSのURL（IP・ポート・`streamid=read:<ID>`）を確認。そのカメラのSRTポート（`8890`～`8893/udp`）がServerへ届くか（firewalld・経路）。Wi-Fi経由になっていないか |
| 表示まで時間がかかる | `ソースが非アクティブのときにファイルを閉じる` がオフか。ネットワークバッファリングを大きくしすぎていないか |
| 映像がカクつく・止まる | OBSの統計でデコード・レンダリングの遅延を確認。`ハードウェアデコード` のオン・オフを切り替えて比較。SRT遅延（`latency`）を `200000` に上げて比較し、結果を記録する |
| 音声が出ない | ソースのミュート状態・音量。カメラPCで `音声を送信する` がオンか。ドックの出力に `AAC` があるか |
| 音声が二重・エコー | 複数のソースがミュート解除されている。配信に使う1ソース以外をミュート |
